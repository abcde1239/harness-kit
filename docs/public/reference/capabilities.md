# 能力与适用范围

[文档导航](../README.md) · [安装](../guides/installation.md) · [使用](../guides/usage.md)

Harness Kit 给现有 Agent 宿主提供项目接入、可恢复工作记录和统一验证。适合已有代码和测试，希望跨宿主保留项目约定、保护人工改动，并判断一次任务是否满足验收的项目。

## 当前解决的问题

| 问题 | 当前实现 | 边界 |
|---|---|---|
| 每个 Agent 需要单独维护项目入口 | 选择宿主后安全生成受管段，共享入口去重，重复接入幂等 | 宿主覆盖规则和真实会话加载需另行核实 |
| 初始化工具覆盖已有指令或框架 | 保留用户正文、CRLF、既有配置和测试布局，受管内容被修改时报告冲突 | 冲突需要审阅合并，不擅自覆盖 |
| 静态检查通过，业务验证却未运行 | run 执行项目已有测试、lint、类型检查或其他配置任务，按 DAG 处理依赖 | 未配置或未选中的验证不会冒充通过 |
| 旧测试绿灯被当作当前证据 | 记录验证范围和输入摘要；源码或配置变化使证据过期 | 任意依赖、环境变量和外部服务变化未全部追踪 |
| 跨会话或多 Agent 交接后丢失目标 | task 保存目标、scope、验收项、备注和下一步，resume 恢复记录 | 不自动重放操作；scope 是协作说明，不是沙箱 |
| 多 Agent 职责模糊，交付后难以集成 | 按需选择产品、设计、架构、前后端、测试、复核和文档提示词，给出文件归属、依赖及验收 | 需要宿主的真实委派工具；角色模板不提供调度器或权限隔离 |
| 不确定 Agent 行为该如何改进 | Agent 专家根据实际行为和产出，判断应约束、增强、简化还是保持现状，并提出范围与验证方法 | 按需使用；建议不等于已批准修改，提示词不提供运行时强制约束 |
| Agent 缺少个人编码和架构习惯的依据 | 从指定项目归纳带来源、反例和范围的画像，按采用状态读取规则并用于复核 | 由 Agent 分析；不训练模型，文档规则未接入工具时不是强制 lint 门禁 |
| 测试通过就直接宣布任务完成 | finish 要求与本任务关联的当前完整验证及逐项人工验收 | 证据文字是否真实满足业务要求由负责人核实 |
| 发布时夹带内部开发资料 | 按允许清单导出、核对实际产物及来源，按需检查历史和公开边界 | 不自动上传、改可见性或清理历史 |

当前能力包含真实命令验证、任务恢复和验收关联。check 仍是只读静态检查；doctor 只诊断，不执行测试。

## 宿主支持分为两层

| 宿主 | 项目指令入口 | 原生插件 |
|---|---|---|
| Codex | AGENTS.md，可选本地 hooks | 提供，隔离 CLI 安装实测通过 |
| Claude Code | CLAUDE.md | 提供，隔离 CLI 安装实测通过 |
| Gemini CLI | GEMINI.md | 未提供专用原生插件 |
| Cursor | .cursor/rules/harness-kit.mdc | 未提供专用原生插件 |
| OpenCode | AGENTS.md | 未提供专用原生插件 |
| DeepSeek Harness | AGENTS.md | 提供 Cordis 原生插件，接口契约测试通过，真实 profile 待验收 |

项目指令适配不等于宿主原生插件；独立 Skill 能否被发现取决于对应宿主设置。所有宿主共用同一项目验证与持久任务核心，不管理模型账号、权限或 Agent 执行循环。

## 与现有工具配合

以下是职责和采用方向的对照，不是效果或性能排名；参考范围为 2026-11-11 调研的公开资料，预览功能可能变化。

| 工具方向 | 可参考的能力 | Harness Kit 的选择 |
|---|---|---|
| [Superpowers](https://github.com/obra/superpowers) | 可组合开发、调试、评审方法和完成前验证 | 保留现有方法，增加项目接入与可检查的验证记录；不强制每个任务使用全套流程 |
| [Spec Kit](https://github.com/github/spec-kit) / [OpenSpec](https://github.com/Fission-AI/OpenSpec) | 规格、变更组织、宿主集成和持久上下文 | 与既有规格流程配合；按需保存工作目标和验收，不另建完整规格引擎 |
| [BMad](https://github.com/bmad-code-org/BMAD-METHOD) | 按工作规模选择路径和专业职责 | 小改动保持轻量，复杂任务才保存方案和分工 |
| [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness) | 插件组合、按需上下文、会话运行时 | 提供可安装的原生 Skill 插件，复用宿主模型循环，不复制其会话或模型平台 |

值得保留的组合是：用户修改保护、跨宿主入口、技术栈无关验证、证据时效与人工验收关联。其他工具也能运行测试，“能执行测试”本身不是独占能力。

后续优先方向是实际宿主新会话验收、DSH profile 安装验证和配置漂移合并，再按真实需求扩展 hooks 与 CI。当前没有后台自主续跑、模型路由、共享知识服务或跨宿主统一调度；多 Agent 提示词需要宿主真实委派工具与用户授权。
