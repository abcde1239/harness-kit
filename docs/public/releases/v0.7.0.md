# v0.7.0 — Extensible Technology Adapters

把更多技术栈接入同一套项目发现与验证流程，保留项目原来的目录和工具链。

## 本版新增

- **识别更多项目入口。** 在 Go 和 JavaScript 之外，识别 Python、Rust、JVM、.NET、PHP、Ruby、C/C++、Dart、Elixir 和 Swift 的常见项目标记。标记用于识别工作区；测试命令不明确时会要求配置。
- **用配置添加自己的技术栈。** 项目根目录的 `harness.adapters.json` 可声明项目标记、排除路径、嵌套工作区规则，以及命令、依赖和超时，无需修改 CLI 或编写 JavaScript 插件。
- **独立配置测试识别。** `tests.detect` 决定哪些文件属于测试，`tests.include` 约束测试所在路径，实际执行仍交给原生测试工具。
- **共用适配接口。** Go、JavaScript、内置项目配方与自定义适配器通过同一注册表合并。多个技术栈可以共存，现有显式配置保持优先。

适配器声明变化后，旧计划和验证记录需要重新确认。本版也修复了 CLI 测试对测试文件加载顺序的依赖。

## 使用

常见项目直接按原有方式接入。需要自定义发现规则时，在项目根目录添加 `harness.adapters.json`：

```json
{
  "schemaVersion": 1,
  "recipes": [
    {
      "id": "elixir",
      "markers": ["**/mix.exs"],
      "nested": "outermost",
      "tests": {
        "detect": ["**/*_test.exs"],
        "include": ["test/**/*_test.exs"]
      },
      "tasks": [{ "id": "test", "argv": ["mix", "test"] }]
    }
  ]
}
```

然后让 Agent 接入项目，或运行 `harness init`。已有 `harness.config.json` 的项目会保留其配置，新的发现结果作为建议供复核。完整规则见[适配器参考](../../../skills/harness-kit/references/adapters.md)，更多配置见[示例](../../../examples/adapters-generic.json)。

## 能力边界

- 项目标记识别不代表对应测试已经运行，也不会执行项目配置文件来探测框架。目标项目仍需自己的运行时、测试工具及依赖。
- 自定义声明按数据读取，不动态加载项目模块，不移动业务代码或测试目录。
- DSH 仍为实验支持，适配 `>=0.2.2-rc.1 <0.3.0` 的 developer preview 接口；真实 profile 安装与模型会话发现尚待验收。
