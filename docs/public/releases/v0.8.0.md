# v0.8.0 — Artifact and Hook Lifecycle Management

Harness Kit 为一次工作分配一个产物目录，让多 Agent 可以共享日志、截图和测试报告。临时产物按保留期清理，发布包与验收资料可以单独保存。新版还会检查 `.harness/` 中误放的测试文件。

- `harness artifacts create <label>` 创建运行目录。所有写入结束后用 `finish <id>` 开始计算保留期。长期引用可以用 `keep <id>` 保留，用 `release <id>` 解除保留。`artifacts clean` 默认预览，默认保留 14 天。
- `harness hooks clean` 独立预览 `.harness/hooks/sessions/` 中的过期快照，默认保留 30 天。清理范围只包含会话快照，运行器与宿主注册继续保留。旧版无活动时间的快照会在再次使用时补记。
- `harness check` 检查 `.harness/` 的文件用途和 `artifacts/` 的目录组织。可识别的测试脚本、夹具和快照应放在框架原有的测试目录。历史散落产物默认告警，便于逐步整理。

两种清理命令都需要传入 `--yes` 才会删除符合条件的文件。详见[产物管理](../reference/artifacts.md)和[目标项目布局](../reference/project-layout.md)。

## Upgrade

用 Release 中对应宿主的完整 Skill 或插件替换旧版本，保留定制内容，然后开启新会话。已经启用 Codex Hooks 的项目可以重新运行 `harness init --hooks` 更新项目内的运行器。现有配置可以继续使用，保留期字段为可选项。升级后重新运行项目验证可刷新旧证据。
