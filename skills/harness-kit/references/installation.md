# Install or migrate Harness Kit from a link

Use this workflow when the user asks to install the plugin from a repository or Release link. Read that source's root `INSTALL.md` or the same Release's `AGENT-INSTALL.md` first. Loading this Skill does not prove that the target host has been installed; verify the actual source and host state.

Identify the current or target host, show the default absolute path, and ask whether to use it or another directory. Defaults are `%LOCALAPPDATA%/harness-kit/plugins/<host>` on Windows and `~/.local/share/harness-kit/plugins/<host>` elsewhere; the standalone Skill defaults to `~/.agents/skills/harness-kit`. Use an already specified location without asking again. Do not write until the user answers. Validate a custom location as a persistent absolute path; the host manages its own cache directory separately.

The distributed Skill includes `scripts/install-plugin.mjs`. Locate it relative to the `SKILL.md` that was actually loaded. If absent, download the source's standalone `install-plugin.mjs`, inspect it locally, and execute it with Bun; never pipe a network script into a shell. Supply `--source`, `--host`, and `--location`; run `--dry-run` first, then complete installation without that flag. For DSH, supply `--profile` and verify whether Desktop uses its bundled CLI. If a Release has no installer attachment, the repository's `scripts/install-plugin.mjs` may be used, but explain its version difference from the Release assets and do not invent a download URL.

Resolve repository roots, Releases, Release ZIPs, and repository documentation links according to the installation instructions. Obtain the package and `SHA256SUMS` from the same source. Report missing Bun or host tools precisely; do not change global permissions or PATH, or install other tools automatically. Handle conflicting sources, user edits, trust, and cache failures according to the observed result. Do not delete files or switch installation types to hide a failure.

Report installation and configuration as complete only after the host's required steps and status checks succeed. Investigate a `partial` result further. Verify discovery by a new model session separately; leave it unconfirmed when there is no evidence. An installation request alone does not authorize project initialization. Follow the Skill's onboarding workflow when project integration is also requested.
